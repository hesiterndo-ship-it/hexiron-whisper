# اتصال HEXIRON WHISPER به فروشگاه (hexiron-sales)

بعد از بررسی کد واقعی `HexironSales_ready` این‌ها انجام شد (نسخه‌ی به‌روزشده‌ی فروشگاه رو هم دریافت کن):

## سمت فروشگاه (HexironSales_ready)
1. محصول `whisper` به‌صورت خودکار به جدول `products` اضافه می‌شه (چه دیتابیس تازه باشه چه از قبل
   `guard`/`music` داشته باشه) — نیازی به کار دستی نیست، فقط بات فروش رو با کد جدید ری‌استارت کن.
2. یک فیلد جدید **tier** (`pro` یا `business`) به پکیج‌ها (`plans`) و لایسنس‌ها (`licenses`) اضافه شد.
   این چیزیه که به بات‌های زیرمجموعه می‌گه چه سقفی اعمال کنن (فیلد `plan_name` قبلی فقط اسم نمایشیه،
   مثل «۱ ماهه»، و برای منطق برنامه قابل‌اتکا نبود).
3. توی پنل ادمین (`/adminpanel` → `🤖 پنل ادمین ربات‌های عمومی` → `💰 مدیریت پکیج‌ها` → محصول
   `🤫 نجوا` → `➕ پکیج جدید برای این محصول`): بعد از وارد کردن اسم/مدت/قیمت پکیج، یک قدم جدید ازت
   می‌پرسه پکیج **Pro** باشه یا **Business** (Free همیشه پیش‌فرض بدون‌لایسنسه).
4. همین قدم به فلوی **🎁 افزودن لایسنس دستی** هم اضافه شده.
5. هر محصول و هر پکیج داخل همون منو حالا دکمه‌ی فعال/غیرفعال کردن، تغییر نام، و حذف هم داره
   (حذف اگه سابقه‌ی فروش داشته باشه، برای حفظ گزارش‌ها فقط غیرفعال می‌کنه نه پاک).
6. توی فلوی خرید مشتری (`/shop`)، هر مرحله یه دکمه‌ی «❌ انصراف از خرید» داره که همیشه در دسترسه.
5. `GET /api/v1/license` حالا یک فیلد `tier` هم برمی‌گردونه، در کنار `plan` (اسم نمایشی) و `active`.

## سمت بات نجوا (این ریپو)
- `services/licensing.py` نتیجه رو کش می‌کنه و اگه فروشگاه موقتاً در دسترس نبود، تا `LICENSE_GRACE_SECONDS`
  از آخرین پلن معتبر استفاده می‌کنه (fail-open کنترل‌شده، نه قطع ناگهانی سرویس مشتری پولی).
- سقف واقعی هر tier (`whispers_per_day`, `groups`) از `config.PLAN_LIMITS` اعمال می‌شه.
- ستون `owner_id` روی جدول `groups` اضافه شد تا سقف «تعداد گروه» واقعاً روی هر مدیر چک بشه.
- `/whisper_refresh`: مدیر گروه بعد از خرید/ارتقا در فروشگاه این رو می‌زنه تا بدون صبر برای انقضای
  کش (۵ دقیقه پیش‌فرض)، پلن جدید فوراً اعمال بشه.

## تنظیمات لازم (`.env` بات نجوا)
```
SALES_API_URL=https://<دامنه‌ی واقعی سرور HexironSales_ready>
SALES_API_KEY=<همون مقداری که در .env فروشگاه به‌عنوان API_KEY گذاشتی>
PRODUCT_CODE=whisper
```
مقدار `SALES_API_KEY` توی بات نجوا باید عیناً همون `API_KEY` باشه که در `.env` ریپو
`HexironSales_ready` تنظیم کردی (طبق کامنت خود `config.py` فروشگاه: «همین مقدار رو باید توی
`.env` ربات‌های زیرمجموعه هم بذاری»).

## تست سریع سرتاسری
1. یک گروه تست بساز، بات نجوا رو اضافه کن، `/whisper_on` بزن (باید با پلن Free فعال بشه: ۵۰
   نجوا/روز، ۱ گروه).
2. در بات فروش، `/adminpanel` → `🤖 پنل ادمین ربات‌های عمومی` → `🎁 افزودن لایسنس دستی` →
   محصول «نجوا» → سطح **Pro** → همون
   `group_id` → چند روز اعتبار.
3. داخل گروه تلگرام، مدیر گروه دستور `/whisper_refresh` رو بزنه — باید سقف روزانه «نامحدود» و
   سقف گروه «۱۰» نمایش داده بشه.
4. همین رو با سطح **Business** هم تست کن — باید سقف گروه هم «نامحدود» بشه.

## نکته درباره‌ی دسترسی به ریپوی گیت‌هاب
گیت‌هاب برای این محیط، صفحه‌ی `tree/` رو برای کرالرها می‌بنده و API عمومی‌اش هم به‌خاطر IP مشترک
Rate-limit می‌شه — به همین خاطر تحلیل بالا از روی فایل zip واقعی که آپلود کردی (`HexironSales_ready`)
انجام شد، نه از روی لینک گیت‌هاب. اگه بعداً ساختار دیتابیس یا endpointها رو در ریپوی اصلی تغییر بدی،
کافیه دوباره یک zip به‌روز آپلود کنی تا دوباره هماهنگش کنم.
